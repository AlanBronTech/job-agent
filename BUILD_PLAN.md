# Build plan

Seven phases. Each is one Claude Code session, each ends with something that
runs. Do not start a phase before the previous one's exit criterion is met.

Timebox: **two weeks to first real application generated by the tool.** If it
slips past that, cut scope — drop Phases 5 and 6 entirely.

---

## Phase 0 — Profile as data (do this yourself, not with Claude Code)

The scaffolded `profile/*.yaml` files are drafts built from prior conversations.
They contain errors and gaps. Fix them by hand before writing any code. Every
downstream output is only as good as this.

Checklist:
- [ ] Every role has correct dates, company, title
- [ ] Every achievement bullet has a number in it or is deleted
- [ ] Every bullet is tagged with at least one theme
- [ ] Story bank has situation/action/result written out in full, in your voice
- [ ] `voice.md` has 3 real cover letters you were happy with, pasted in full

**Exit criterion:** you'd be comfortable if an interviewer read the YAML.

## Phase 1 — Skeleton, config, profile loader

Prompt:

> Read CLAUDE.md. Set up the project skeleton: pyproject.toml with uv, the
> package layout described in CLAUDE.md, a config module reading from .env
> (ANTHROPIC_API_KEY, ANTHROPIC_MODEL, DRIVE_RESUME_FOLDER_ID,
> DRIVE_COVERLETTER_FOLDER_ID, DB_PATH), and `core/profile.py` which loads and
> validates profile/*.yaml into pydantic models. Add `jobagent profile validate`
> as the first CLI command — it should print a summary and fail loudly on
> schema errors. Write unit tests for the loader including malformed input.

**Exit:** `uv run jobagent profile validate` prints your role and story counts.

---

## Phase 2 — JD ingestion and parsing

Prompt:

> Implement JD ingestion. `jobagent jd add` accepts --file, --stdin, or opens
> $EDITOR for paste. It calls the LLM via adapters/llm.py using
> prompts/parse_jd.md to produce a structured JobDescription (pydantic):
> title, company, location, work_type, salary_range, seniority, must_haves[],
> nice_to_haves[], tech_stack[], responsibilities[], red_flags[], source,
> raw_text, ingested_at. Persist to SQLite via core/store.py. Add
> `jobagent jd list` and `jobagent jd show <id>`. Mock the LLM in tests; add
> three real JD fixtures.

**Exit:** you can paste a Seek JD and get a clean structured record back.

---

## Phase 3 — Fit scoring and go/no-go

The highest-value phase. This is the one that saves you days.

Prompt:

> Implement core/scoring.py. Given a JobDescription and the Profile, produce a
> FitAssessment: overall_score 0-100, per-requirement match (met / partial /
> gap) with the evidence bullet from the profile that supports it,
> gap_list with severity, verdict (apply / apply_with_caveats / skip) with a
> one-paragraph blunt rationale, emphasise[] (what to lead with),
> challenge_points[] (what a recruiter or interviewer will push back on), and
> suggested_talking_points[]. Use prompts/score_fit.md. The prompt must forbid
> claiming any capability not evidenced in the profile. Add `jobagent score
> <jd_id>` with rich formatted output.

**Exit:** run it against the Toshiba JD. If it doesn't surface the tech-stack
mismatch as a challenge point, the prompt is wrong — iterate until it does.

---

## Phase 4 — Document generation to Drive

Prompt:

> Implement adapters/docx_writer.py rendering to the format in CLAUDE.md, and
> core/generate.py producing: (a) a tailored resume that selects and reorders
> bullets from the profile based on the FitAssessment, never inventing content;
> (b) a cover letter following profile/voice.md; (c) answers to free-text
> application questions supplied via --questions. Then adapters/drive.py to
> upload into the configured folders with naming
> `AlanBron_Resume_<Company>_<YYYYMM>.docx`. Add `jobagent generate <jd_id>
> --resume --cover --answers`. Include a validation step that flags any factual
> claim in the output not traceable to profile/, and any banned phrase from
> voice.md.

**Exit:** a generated resume and cover letter land in Drive and need less than
ten minutes of editing.

---

## Phase 5 — Pipeline tracking

Prompt:

> Extend core/store.py with an applications table: jd_id, status enum
> (identified, applied, recruiter_contact, screening, interview_1,
> interview_2, offer, rejected, withdrawn, ghosted), applied_date, recruiter
> name/agency/contact, next_action, next_action_date, notes, outcome. Add
> `jobagent apply <jd_id>`, `jobagent status`, `jobagent update <id>`,
> `jobagent followup` (shows overdue actions), and `jobagent report
> --fortnight` producing the Workforce Australia activity summary.

**Exit:** `jobagent report --fortnight` gives you the reporting list without
you reconstructing it from memory.

---

## Phase 6 — Gmail auto-triage on a schedule

Prompt:

> Implement adapters/gmail.py: OAuth installed-app flow, token cached to
> ~/.job-agent/gmail_token.json, read-only scope. Fetch messages matching
> configured queries (Seek and LinkedIn job alerts) since last poll. Parse each
> alert into candidate leads: title, company, location, salary if present,
> snippet, and the source URL as an opaque string. DO NOT fetch those URLs.
> Score each lead against the profile using a cheap triage prompt
> (prompts/triage_lead.md) and store as leads with a triage_score. Add
> `jobagent poll` and `jobagent leads --min-score 60`. Include a launchd plist
> (macOS) or systemd timer for a twice-daily run.

**Exit:** twice a day you get a shortlist; you open only the ones worth opening,
paste the JD, and go to Phase 3.

---

## Phase 7 — Eval harness and interview prep

Prompt:

> Build evals/: a set of past JDs with recorded real outcomes in
> evals/cases.yaml. Run the fit scorer over them and report correlation between
> predicted score and actual outcome, plus per-case diffs. Add a prompt-
> regression mode that reruns after prompt edits and shows what changed. Then
> implement core/prep.py: given a jd_id plus optional interviewer names and
> roles, generate likely questions mapped to specific stories from the story
> bank, with the challenge_points from the FitAssessment as the hard questions.

**Exit:** you can say in an interview "I measured it against fifteen real
applications and here's what the scorer got wrong" — which is the difference
between this and every other LLM wrapper on a resume.
